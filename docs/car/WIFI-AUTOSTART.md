# Wi-Fi машинки: автозапуск точки доступа при загрузке

Сделано под реальную систему машинки: профиль `CarHotspot` (пароль 12345678),
ID из `/boot/firmware/car_id.txt`, точка на внешнем USB-адаптере (любая из ваших
версий — AU или BU), встроенный `wlan0` остаётся для домашних сетей и SSH.
**`main.py` менять не нужно.**

## Почему без «подождать N секунд»

Скрипт с задержкой угадывает момент, когда адаптер готов, — и на холодном старте
не угадывает. Поэтому включением занимается не скрипт, а сам NetworkManager:
профиль `CarHotspot` получает `autoconnect=yes` и привязку к **драйверу**
USB-адаптера. NetworkManager поднимет точку ровно тогда, когда адаптер появится
в системе, — хоть на пятой секунде загрузки, хоть на тридцатой, хоть когда ты
воткнёшь адаптер в уже работающую машинку. Ждать нечего, гонки нет по построению.

Адаптер скрипт находит **по шине USB**, а не по имени драйвера: внешний всегда
висит на USB, встроенный у малинки — на SDIO. Поэтому находится любой адаптер,
хоть AU, хоть BU, хоть будущий третий, и версия драйвера значения не имеет.

А привязывается профиль к **драйверу** (`match.driver`), причём списком сразу под
обе версии адаптера — `88XXau`, `8812au`, `88x2bu`, `rtl88x2bu`, `rtw_8822bu` и
прочие их написания, плюс тот, что реально найден на этой машинке. Имя интерфейса
(`wlx…`) и MAC у каждого адаптера свои, а драйвер один и тот же на всю партию —
значит **один образ заводится и на AU, и на BU**, клонирование работает как
раньше. Лишние имена в списке не мешают: они просто ни с чем не совпадают.

Заодно это гарантирует, что точка никогда не займёт `wlan0`: без внешнего
адаптера она просто не поднимется, а домашняя сеть и SSH останутся на месте.

Ещё две вещи, которые при автостарте иначе потерялись бы:

- **Имя сети из `car_id.txt`.** Сервис `car-ap-ssid` правит имя прямо в файле
  профиля **до** запуска NetworkManager — правит файл, пока NM ещё не работает,
  поэтому дёргать `nmcli` и ловить момент не нужно. Клонировал флешку, поменял
  число в `car_id.txt` — сеть уже с новым именем, как и BLE-имя с именем хоста.
- **Мощность передатчика.** Те же «стероиды», что в `main.py` (`iw reg set KZ`,
  `txpower fixed 2300`), вешаются на диспетчер NetworkManager: он вызывается
  ровно в момент, когда `CarHotspot` поднялся, — и при автостарте, и при команде
  с телефона.

## Установка (один раз на эталонной флешке, ID 27)

1. USB-адаптер Wi-Fi должен быть воткнут — любой из ваших, AU или BU.
2. Зайди на машинку по SSH — годится и кабель (`10.55.0.1`), и домашний Wi-Fi
   (`raspberry<ID>.local`): точка поднимается на внешнем адаптере, `wlan0` не
   трогается, так что сессия не оборвётся.
3. Скопируй скрипт и запусти:

   ```
   scp setup-car-ap.sh sultan@raspberry27.local:~
   sudo bash setup-car-ap.sh
   ```

   Если сидишь в VS Code по Remote-SSH — просто перетащи файл мышкой в панель
   Explorer, это то же самое.

   Он печатает каждый шаг: какой нашёл `car_id.txt`, какой ID, какой адаптер и
   драйвер, что прописал в профиль. Ничего не создаёт с нуля и не удаляет —
   только правит существующий `CarHotspot`.
4. `sudo reboot` → через полминуты `Car_27_WiFi` должна появиться сама.
5. Снимай образ как обычно (`КАК_КЛОНИРОВАТЬ.md`) — настройка уезжает в клоны
   вместе с системой.

## Что именно меняется на машинке

| Что | Было | Стало |
|---|---|---|
| профиль `CarHotspot` | `autoconnect` выключен, поднимался только командой с телефона | `autoconnect=yes`, приоритет 100, повторы без ограничения, сон Wi-Fi выключен, привязка к драйверам внешних адаптеров (AU и BU) |
| `/usr/local/sbin/car-ap-ssid` + `car-ap-ssid.service` | — | новый: пишет SSID из `car_id.txt` в профиль до старта NetworkManager |
| `/etc/NetworkManager/dispatcher.d/90-car-ap-boost` | — | новый: `iw reg set KZ` и `txpower 2300` при каждом подъёме точки |
| `main.py` | — | **не трогаем** |
| домашние сети (ALTEL, QEC_Freedom_Guest) | — | **не трогаем**, они на `wlan0` |

## Почему `main.py` можно не трогать

В нём уже есть `hotspot_active()` — проверка «точка уже в эфире?» перед
`nmcli con up`. При автостарте она вернёт `True`, и обработчик команды `wifi`
честно напишет в лог «точка уже в эфире — не перезапускаю» и выйдет. То есть
кнопка на телефоне остаётся рабочей страховкой, но больше ничего не ломает.

Две строки `nmcli con modify CarHotspot …` (ssid и interface-name) в обработчике
теперь избыточны — они прописывают то же самое, что уже стоит в профиле. Мешать
не мешают, удалять не обязательно.

Отдельно стоит знать про `find_ap_interface()` в `main.py`: он ищет адаптер по
подстрокам `8812` и `88xx` в имени драйвера. Версия BU (драйвер `88x2bu`) под
эту проверку **не попадает**, и функция молча возвращает `wlan0` — то есть по
команде с телефона точка на таких машинках поднималась на встроенном адаптере,
а не на внешнем. Автозапуск этим не страдает (он ищет по шине USB), но если
захочешь починить и ручной путь — там достаточно проверять шину так же:
`'/usb' in os.path.realpath(f'/sys/class/net/{iface}/device')`.

Команда `wifioff` тоже работает: `nmcli con down CarHotspot` гасит точку, и до
перезагрузки NetworkManager сам её не поднимет. Если нужно, чтобы выключение
переживало перезагрузку — `sudo nmcli con modify CarHotspot connection.autoconnect no`.

## Проверка после перезагрузки

```
nmcli -f NAME,DEVICE,STATE con show --active   # CarHotspot на wlx… (не на wlan0!)
iw dev                                          # type AP у внешнего адаптера
ip -4 addr show <иface адаптера>                # 10.42.0.1/24
journalctl -b -t car-ap-ssid -t car-ap-boost    # что сделали сервис и диспетчер
```

Если точки нет: `journalctl -u NetworkManager -b | grep -i carhotspot` — там
видно, ждёт ли NM адаптер или профиль не подошёл ни одному устройству.

## Если понадобится гонять без USB-адаптера

Точка привязана к его драйверу, поэтому без адаптера она не поднимется. Разово
снять привязку (тогда точка встанет на встроенный `wlan0`, и домашняя сеть с SSH
на нём пропадут):

```
sudo nmcli con modify CarHotspot match.driver ""
sudo nmcli con up CarHotspot
```

Вернуть обратно — снова запустить `setup-car-ap.sh`.

## Откат целиком

```
sudo nmcli con modify CarHotspot connection.autoconnect no
sudo systemctl disable --now car-ap-ssid.service
sudo rm /etc/systemd/system/car-ap-ssid.service /usr/local/sbin/car-ap-ssid \
        /etc/NetworkManager/dispatcher.d/90-car-ap-boost
sudo systemctl daemon-reload
```

Профиль `CarHotspot` остаётся как был, всё возвращается к «поднимается только по
команде с телефона».

## Почему не другими способами

| соблазн | почему нет |
|---|---|
| `rc.local` / `cron @reboot` + `sleep` | угадываем время готовности адаптера; на холодном старте не угадаем |
| свой systemd-сервис `After=network.target` | `network.target` не гарантирует, что адаптер уже появился |
| `hostapd` + `dnsmasq` | конкурируют с NetworkManager за адаптер — именно тот конфликт, которого избегаем (в `КАК_КЛОНИРОВАТЬ.md` они не зря выключены) |
| привязка профиля к MAC или к имени `wlx…` | у каждого адаптера свои — клон флешки перестанет поднимать точку |
| поиск адаптера по имени драйвера, как в `main.py` | имён зоопарк (`8812au`, `88XXau`, `88x2bu`, `rtw_8822bu`…) — версия BU под такую проверку не попадает |
| `nmcli con up` при каждом старте из `main.py` | на уже поднятой точке это переактивация: клиенты вылетают, видео рвётся |
